# Снапшоты namespace

Снапшот сохраняет данные выбранных томов и пины зависимостей. Секреты по умолчанию
не экспортируются: обычный импорт рассчитан на тот же сервер с прежними ключами.
Экспорт и импорт выполняются при остановленном namespace.

## Прогресс скачивания

При скачивании снапшота интерфейс показывает полученные байты, общий размер и
процент, если сервер сообщил размер. При неизвестном размере остаются счётчик
байтов и индикатор ожидания. Показывается время выполнения; после 30 секунд без
обновления прогресса появляется сообщение об ожидании ответа. Это не означает,
что операция завершилась ошибкой или была отменена.

Прогресс приходит через события `snapshot_progress` с `phase: downloading`,
`receivedBytes` и `totalBytes` (значение <= 0 означает неизвестный размер).
Импорт продолжает показывать прогресс по томам. Завершение, включая использование
уже скачанного архива, закрывает ожидание; ошибка фоновой загрузки открывает
окно с подробностями. Остальные события приложений не считаются прогрессом загрузки.

В desktop обработчик событий подписывается до сигнала Wails `wails:runtime:ready`.
Без этого сигнала Wails оставляет нативные события в очереди и страница не получает
ни прогресс, ни завершение. При переподключении мост передаёт `Last-Event-ID`
последнего полностью полученного события: пропущенное завершение воспроизводится
из буфера daemon и закрывает окно автоматически. Частично полученный SSE frame
не сдвигает позицию восстановления.

Асинхронные запросы возвращают `operationId`; он также присутствует в событиях.
`GET /api/v1/snapshots/operations/{id}` возвращает последнее состояние конкретной
операции в активном workspace/namespace. При создании namespace из снимка
результат также доступен из namespace, где начался запрос: импорт идёт до
активации нового namespace. Другая конфигурация и другой workspace доступа не
получают. Replay событий уже завершённой операции не открывает окно повторно.
Активные операции и последние 128
завершённых результатов хранятся отдельно от общего SSE-буфера до перезапуска
процесса. Пока окно ждёт результат, UI проверяет его каждые 3 секунды и при resync,
поэтому вытеснение события из буфера не оставляет окно зависшим. Повторное чтение
состояния не считается новым прогрессом. Если результат уже недоступен после
перезапуска или вытеснения истории, UI показывает ошибку с неизвестным исходом,
не объявляя импорт успешным.

Общего лимита времени скачивания нет. При ожидании заголовков или новых байтов
действует таймаут 30 секунд; каждый полученный байт начинает отсчёт заново.
При остановке передачи попытка прерывается и запускается существующий повтор
через 3 секунды, с докачкой через Range, если сервер её поддерживает. Лимиты:
3 последовательные неудачные попытки без прогресса докачки. Счётчики ошибок
сбрасываются только при получении новых байтов в ответе `206` на запрос Range.
Байты полного ответа `200`, в том числе при игнорировании Range и загрузке с нуля,
счётчики не сбрасывают. Общего лимита попыток при успешной докачке нет. Ошибка SHA256 не повторяется.

При докачке проверяются смещение и длина `Content-Range`, длина полученного
ответа и сохранённый в текущей операции ETag либо Last-Modified. Неверный
частичный ответ не дописывается в архив и не сбрасывает счётчик ошибок.
Передача запрашивается без изменения кодировки байтов (`Accept-Encoding: identity`).

## Архив

```text
snapshot.zip
├── meta.json
├── secrets.json (только с --include-secrets)
├── postgres3.tar.zst
└── seaweedfs2.tar.zst
```

`meta.json` содержит дату создания, имена архивов и ownership/mode корней томов.
Поле `dependencies` сохраняет image pin и `volumeGen` зависимостей, данные которых
попали в архив. Pin Keycloak переносится вместе с PostgreSQL, где хранится его БД.
Rollback target сохраняется только вместе с соответствующим резервным поколением
тома. Частичный экспорт не переносит pins невыбранных зависимостей.

Для переноса с ключами: `citeck snapshot export --include-secrets --dir /absolute/path`.
API: `POST /api/v1/snapshots/export` с JSON `{"includeSecrets": true}`; отсутствующее
поле означает false. Выбор томов (`volumes`) работает независимо от этого параметра.

`secrets.json` — JSON object `имя → значение`, без ID исходного workspace/namespace
и без ciphertext исходного vault. В него входят сохранённые NAMESPACE secrets,
включая сгенерированные ключи SeaweedFS, а также эффективные JWT/OIDC/admin/SA.
Системные ключи используют зарезервированные имена `@citeck/system/jwt`,
`@citeck/system/oidc`, `@citeck/system/admin_password`, `@citeck/system/citeck_sa`.
Они не пересекаются с допустимыми именами workspace secrets. Registry/git credentials
не экспортируются. Файл и ZIP имеют mode 0600; содержимое secrets.json — plaintext.
Без параметра файл отсутствует; vault для такого экспорта не читается.

## Восстановление

Секреты записываются в целевой namespace и шифруются его vault. Одноимённые значения
заменяются; прочие namespace secrets и другие namespaces не изменяются. Системные
ключи также сохраняются в vault целевого namespace: глобальные `_sys_*` профиля
не заменяются. Генерация и reload используют эти overrides, а последующая смена
admin-пароля сохраняет override этого namespace. После
успешного восстановления первый Generate использует импортированные ключи,
а не генерирует новые. Старые архивы без `secrets.json` не меняют секреты.

Пины применяются до первой генерации при создании namespace и server install.
Для обычного импорта состояние активного Runtime обновляется и сохраняется.
Для старых архивов без pins остаётся вывод версии/поколения из восстановленных
данных; точное исходное состояние гарантирует только новый metadata format.
Для PostgreSQL отсутствие `18/docker/PG_VERSION` не прерывает проверку: версия
читается из следующего известного расположения, включая корневой `PG_VERSION`
старых томов. Ненулевой код `cat` сохраняется вместе с диагностикой; ошибка Docker
остаётся отдельной ошибкой проверки.
При последующей миграции перед запуском временных БД скачиваются отсутствующий
образ исходной версии и все образы целевых версий. Уже имеющийся исходный образ
используется без повторного pull. Ошибка скачивания завершает этап `pull-image`
до запуска исходной БД и создания целевого тома.
Журналы и результаты прежней миграции восстановленных зависимостей сбрасываются:
они описывают заменённые данные. Snapshot не переносит незавершённую миграцию;
экспорт запрещён при открытом recovery journal.

До изменения томов проверяются metadata, наличие всех data files, `secrets.json`,
доступ к vault и целостность tar/compression. После проверки, до замены томов,
в состоянии целевого namespace сохраняется `snapshotImportPending`. Пока отметка
стоит, обычный старт, запуск/перезапуск приложения, автостарт после рестарта
Launcher, экспорт и новая миграция запрещены. Повторный импорт разрешён.

Секреты и пины (включая очистку прежнего журнала миграции восстановленных
зависимостей) фиксируются одной транзакцией после успешной распаковки всех томов.
В desktop это SQLite transaction; на сервере — owner-only файловый journal с
before-images, commit marker, atomic file writes и fsync. Незакоммиченный journal
отменяется, зафиксированный дозавершается при следующем открытии хранилища,
загрузке namespace или повторном импорте. Полузаписанные метаданные не выдаются.
Секреты шифруются текущим ключом vault внутри commit; ключи и пины Runtime
меняются только после успешного commit. Тогда же снимается pending-отметка.

Ошибка импорта не вызывает автоматический запуск, в том числе через обычный
`citeck snapshot import`, создание namespace или server install. Если ошибка
возникла до замены томов, их данные не меняются. После начала замены namespace
остаётся остановленным; поддерживаемый путь завершения — повторить импорт.
Транзакция охватывает метаданные, а не содержимое Docker volumes. При I/O ошибке
в распаковке данные могут остаться частичными; это не полный rollback томов.

На сервере в `volumes.bak-*` перемещаются только заменяемые тома; остальные остаются
на месте. Backup сохраняется для восстановления. Desktop очищает только выбранные
named volumes. Копирования внешнего S3 backend здесь нет.

## Границы полноты

Это backup томов и части состояния, а не полный перенос установки на другую
машину. Оставшиеся пропуски и решения — в [аудите снапшотов](reviews/snapshots-audit.md).
