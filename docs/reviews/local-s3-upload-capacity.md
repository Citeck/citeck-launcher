# Локальная загрузка в S3: ограничение свободного места

Проверено 2026-10-09 для namespace `3q5h43y`, Launcher 2.16.2,
ecos-content 1.7.2 и SeaweedFS 4.48. Запрос доходит до S3, но SeaweedFS
возвращает `no volume server capacity registered yet` и пишет
`disk free < required 1.00%`: доступно около 11.3 GiB на разделе 1.8 TiB,
а порог составляет около 18.3 GiB. Свободные блоки, зарезервированные файловой
системой для root, не равны месту, которое SeaweedFS учитывает как доступное.

В `weed mini` версии 4.48 порог `miniVolumeMinFreeSpace = "1"` задан в коде;
обычный `volume.minFreeSpace` не является флагом mini. См.
https://github.com/seaweedfs/seaweedfs/blob/4.48/weed/command/mini.go

Пока место ниже порога, для нового тома нет допустимого volume server и
загрузка завершается ошибкой. Конфигурация, ключи и пользовательские тома
при диагностике не изменялись, второй Launcher daemon не запускался.

Для исправления необходимо освободить доступное место выше порога либо
выбрать другое хранилище/отдельно согласованное изменение backend. Удаление
файлов за пределами Solution требует точного пути и явного разрешения;
никакая внешняя очистка не выполнена. Доступные счётчики и результаты
диагностики сохранены в `.tmp/local-s3-upload/diagnosis.json` Solution.

## Результат

Пользователь освободил место самостоятельно. После этого доступно около
181.5 GiB, ошибки выделения тома прекратились без изменения конфигурации
или перезапуска Launcher. Реальная загрузка 1 MiB через ECOS и последующее
скачивание прошли с совпадением содержимого и SHA256. Созданная для проверки
временная запись удалена через Records API. Кэш Go не очищался, пользовательские
данные и настройки не изменялись. Новая версия Launcher для этого не требуется.
