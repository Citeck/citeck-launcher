# MongoDB при создании namespace

При создании namespace через API (включая desktop и Quick Start) и `citeck install`
launcher проверяет образ eproc в выбранном, разрешённом комплекте:

- eproc ниже **2.33.0** — сохраняет `mongodb.enabled: true`;
- eproc **2.33.0** и новее — использует стандартный режим нового namespace без MongoDB;
- неизвестный тег (`snapshot`, `latest`, образ по digest, даже с указанным тегом) — включает MongoDB;
- комплект без eproc — не включает MongoDB.

Используются общие `deps.Version`, `deps.ParseImageVersion` и сравнение версий.
Сравнение идёт по числовой части версии, постфиксы игнорируются: например,
`2.33.0-snapshot`, `2.33.0-v2`, `2.33.0-RC2` и `2.33.0-rc.1` достигают порога,
а `2.30.7` с любым постфиксом требует MongoDB. Поддерживаются также префикс
`v`, постфиксы с `_`, `.`, `+` и произвольный текст после числовой версии.
Явный `mongodb.enabled` в шаблоне имеет приоритет над автоматическим выбором.
Решение принимается после окончательного выбора комплекта, включая разрешение `LATEST`.
Версия конфигурации нового namespace остаётся актуальной (`apiVersion: v2`).

При загрузке, смене комплекта и обновлении существующего namespace автоматический
выбор повторно не выполняется: MongoDB не удаляется вследствие обновления eproc.
Существующие namespace, созданные без MongoDB для старого eproc, нужно исправить
в их `namespace.yml`, затем применить конфигурацию и перезапустить namespace:

```yaml
mongodb:
  enabled: true
```

В частности, это требуется для `enterprise:2026.1` с eproc `2.30.7`.
Включение MongoDB возвращает контейнер, datasource и зависимость eproc от MongoDB.
Без datasource старый eproc использует встроенный адрес `localhost:27017` и
завершается с `MongoTimeoutException` / `Connection refused`.
Правки описания образов в комплекте или datasource в `workspace-v1.yml` сами по
себе не включают MongoDB на уровне namespace.
