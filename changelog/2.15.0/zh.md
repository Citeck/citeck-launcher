## 变更
- **额外的数据库和向量存储现在在 `additionalApps:` 中声明**，写作带有 `type: POSTGRES` 或 `type: QDRANT` 的条目，条目携带哪些设置由类型决定。这取代了 2.14.0 引入的独立 `databases:` 部分——一份自定义服务列表，而不是两套机制。声明的集群或存储仍然拥有内置组件的一切：版本锁定、带世代计数器的卷、主版本迁移和回滚。
- **此类服务是否存在由 bundle 决定**，即看 bundle 是否指定其镜像——这与 qdrant 已遵循的规则相同。`requiredBy` 键连同它所代表的开关一并删除：不包含该服务的发行版也不包含其数据库，无需再同步任何东西。
- **workspace 配置中的密钥。** 新的 `secrets:` 部分按 id 列出密钥，服务通过 `${secret:<id>}` 引用它们——可用于环境变量、命令、init 容器、cloud config，或 `type: POSTGRES` 条目的 `password:`。workspace 中的值是默认值：每个 namespace 在首次需要时保存自己的副本并一直保留，因为数据库密码存放在数据卷中，事后更改会使服务无法连接。设置主密码后副本加密存储（一旦设置即被加密）；桌面环境在没有主密码时仍可启动。引用的密钥没有值的服务不会启动，依赖它的一切也不会启动。
- **observer 现在是配置，而不是启动器代码。** observer 及其数据库在 workspace 配置中声明（两个官方 workspace 都包含该配置块），数据库密码为 workspace 密钥。由此生成的容器与之前版本完全相同，因此升级不会重建它们，observer 的数据、版本锁定和卷保持不变。不含该配置块的 workspace 配置不会运行 observer。
- **`additionalApps:` 中自定义服务的镜像同样由 bundle 决定**，与其他所有服务一致：条目自己的 `image:` 只是默认值，仅在 bundle 未以该条目名称指定镜像时使用；没有 `image:` 的条目只有在 bundle 指定镜像时才会运行。无法以此方式重新声明工作区 `webapps:` 中列出的平台 webapp——此类条目会被跳过，并在日志中记录错误。条目还支持 `cloudConfig:`，即启动器交给在此处停止、改从 IDE 运行的服务的配置。

## 修复
- **`citeck deps upgrade` 现在可用于在 workspace 中声明的数据库或向量存储。** 此类集群此前显示为可升级，但由于启动器不认识该 id、没有对应的计划，升级会以内部错误失败。现在声明的集群会获得与其类型相同的计划和回滚 — `type: POSTGRES` 采用与环境自身数据库相同的转储/恢复，`type: QDRANT` 采用与内置存储相同的卷复制 — 并且各自只操作自己的数据。
- **observer 在桌面环境中恢复启动。** 自 2.14.0 起它会以 `failed to set up container networking … unknown protocol` 失败：启动器把它接收日志的 UDP 端口按 TCP 发布，Docker 在启动容器时拒绝。现在端口保留其声明的协议，未知协议会连同应用名称一起报告。
- **自动更新后窗口标题立即显示新版本。** 以前在重启启动器之前一直显示旧版本，因为版本是在更新后的服务仍在启动时查询的，且没有重试。
