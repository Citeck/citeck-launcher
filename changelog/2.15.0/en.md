## Changes
- **Extra databases and vector stores are declared in `additionalApps:` now**, as an entry with `type: POSTGRES` or `type: QDRANT`, and the type decides which settings the entry carries. This replaces the separate `databases:` section introduced in 2.14.0 — one list of custom services instead of two mechanisms. A declared cluster or store still gets everything a built-in one has: a version pin, a generation-counted volume, a major-version migration and a rollback.
- **The bundle decides whether such a service exists**, by naming its image — the same rule qdrant already followed. The `requiredBy` key is gone with the switch it was: a release that does not ship the service does not ship its database either, and there is nothing to keep in sync.
- **Secrets in the workspace config.** A new `secrets:` section lists secrets by id, and a service refers to one as `${secret:<id>}` — in its environment, command, init containers, cloud config, or the `password:` of a `type: POSTGRES` entry. The value in the workspace is a default: each namespace stores its own copy the first time it needs it and keeps it, because a database password lives in the data volume and changing it later would lock the service out. The copies are kept encrypted once a master password exists (and are encrypted as soon as one is set); a desktop stand still starts without one. A service whose secret has no value is not started, and neither is anything that depends on it.
- **The observer is configuration now, not launcher code.** The observer and its database are declared in the workspace config (both official workspaces carry the block), with the database password as a workspace secret. The containers this produces are identical to the ones previous versions ran, so upgrading does not recreate them and the observer's data, version pin and volume stay as they are. A workspace config without the block runs no observer.
- **The bundle decides the image of a custom service in `additionalApps:` too**, as it does for every other service: the entry's own `image:` is only the default, used where the bundle names no image under the entry's name, and an entry without `image:` runs only where the bundle names one. A platform webapp the workspace lists in `webapps:` cannot be redeclared this way — such an entry is skipped with an error in the log. Entries also accept `cloudConfig:`, what the launcher hands a service you stop here and run from your IDE instead.

## Fixes
- **`citeck deps upgrade` works on a database or vector store declared in the workspace.** Such a cluster was listed as upgradable, but the upgrade then failed with an internal error because there was no plan for an id the launcher did not know. A declared cluster now gets the plan and the rollback of its kind — `type: POSTGRES` the dump/restore of the stand's own database, `type: QDRANT` the volume copy of the built-in store — each addressing its own data.
- **The observer starts on a desktop stand again.** Since 2.14.0 it failed with `failed to set up container networking … unknown protocol`: the launcher published its UDP log port as a TCP one, which Docker rejects when the container starts. A port keeps the protocol it is declared with now, and an unknown protocol is reported with the app's name.
- **The window title shows the new version right after an automatic update.** It kept the old one until the launcher was restarted, because the title was asked for while the updated service was still starting and the question was not repeated.
