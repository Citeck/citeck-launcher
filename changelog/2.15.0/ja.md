## 変更
- **追加のデータベースとベクトルストアは `additionalApps:` で宣言するようになりました。** `type: POSTGRES` または `type: QDRANT` のエントリとして記述し、そのエントリが持つ設定は型によって決まります。これは 2.14.0 で導入された別セクション `databases:` を置き換えるもので、2 つの仕組みではなく 1 つのカスタムサービス一覧になります。宣言されたクラスタやストアは、組み込みのものと同じくバージョンの固定、世代カウンタ付きボリューム、メジャーバージョンの移行とロールバックをすべて備えます。
- **そのサービスが存在するかどうかはバンドルが決めます。** バンドルがイメージを指定するかどうかで決まり、これは qdrant がすでに従っていたのと同じ規則です。`requiredBy` キーは、それが担っていたスイッチとともに削除されました。サービスを含まないリリースはそのデータベースも含まないので、同期すべきものは何もありません。
- **ワークスペース設定のシークレット。** 新しい `secrets:` セクションでシークレットを id ごとに列挙し、サービスは `${secret:<id>}` で参照します。参照できる場所は環境変数、コマンド、init コンテナ、cloud config、`type: POSTGRES` エントリの `password:` です。ワークスペースの値は既定値です。各ネームスペースは初めて必要になったときに自分のコピーを保存し、以後それを保持します。データベースのパスワードはデータボリュームに記録されるため、後から変えるとサービスが接続できなくなるからです。コピーはマスターパスワードがあれば暗号化して保存され（設定された時点で暗号化されます）、デスクトップ環境はマスターパスワードがなくても起動します。値のないシークレットを参照するサービスは起動せず、それに依存するものも起動しません。
- **observer はランチャーのコードではなく設定になりました。** observer とそのデータベースはワークスペース設定で宣言され（公式の両ワークスペースにこのブロックがあります）、データベースのパスワードはワークスペースのシークレットです。生成されるコンテナは以前のバージョンと同一なので、更新しても再作成されず、observer のデータ、バージョンの固定、ボリュームはそのまま残ります。このブロックのないワークスペース設定では observer は起動しません。
- **`additionalApps:` のカスタムサービスのイメージもバンドルが決めます。** 他のすべてのサービスと同じく、エントリ自身の `image:` はデフォルトにすぎず、バンドルがエントリ名でイメージを指定しない場合にのみ使われます。`image:` のないエントリは、バンドルがイメージを指定する場合にのみ起動します。ワークスペースの `webapps:` に挙げられたプラットフォームの webapp はこの方法で再定義できず、そのようなエントリはログにエラーを出してスキップされます。エントリは `cloudConfig:` も受け付けます。これはランチャーで停止して IDE から起動するサービスに渡される設定です。

## 修正
- **workspace で宣言したデータベースやベクトルストアに対して `citeck deps upgrade` が動作するようになりました。** こうしたクラスタは更新可能と表示されていましたが、ランチャーが知らない id には計画がなかったため、更新は内部エラーで失敗していました。宣言されたクラスタは種類に応じた計画とロールバックを受け取ります — `type: POSTGRES` はスタンド本体のデータベースと同じダンプ/リストア、`type: QDRANT` は組み込みストアと同じボリュームコピー — いずれも自身のデータのみを対象とします。
- **デスクトップ環境で observer が再び起動するようになりました。** 2.14.0 以降、`failed to set up container networking … unknown protocol` で失敗していました。ランチャーがログ受信用の UDP ポートを TCP として公開しており、Docker がコンテナ起動時にそれを拒否していたためです。ポートは宣言されたプロトコルを保持するようになり、不明なプロトコルはアプリ名とともに報告されます。
- **自動更新の直後からウィンドウのタイトルに新しいバージョンが表示されます。** 以前はランチャーを再起動するまで古いバージョンのままでした。更新されたサービスがまだ起動中のときにバージョンを問い合わせ、問い合わせを繰り返さなかったためです。
