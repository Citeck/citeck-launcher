## Novidades
- **Armazenamento de conteúdo: banco de dados ou S3.** Um namespace com um bundle Enterprise que inclui o SeaweedFS (o primeiro é o 2026.3-RC6) pode guardar os arquivos enviados no S3 em vez de no seu banco de dados PostgreSQL: escolha **S3 (SeaweedFS)** em **Armazenamento de conteúdo** na caixa de diálogo **Criar namespace** ou **Editar namespace**. **Banco de dados** continua sendo o padrão, e os namespaces existentes continuam guardando o conteúdo no banco de dados. Nos demais bundles Enterprise, o campo aparece, mas a opção S3 fica indisponível, com o motivo.
- Com S3, o launcher inicia o SeaweedFS junto com o namespace e, assim que a plataforma estiver no ar, conecta o ecos-content ao SeaweedFS por conta própria — não há nada a configurar no ECOS. Se um administrador já definiu outro armazenamento como padrão no ECOS, o launcher não mexe nessa escolha. No aplicativo desktop, um aviso no painel mostra o andamento e, se a conexão falhar, oferece **Tentar novamente**; o launcher também tenta de novo por conta própria.
- Um namespace pode passar do banco de dados para o S3 mais tarde, mas não voltar. Os arquivos enviados antes da mudança continuam no banco de dados.
- No aplicativo desktop, parar o SeaweedFS em um namespace que guarda o conteúdo no S3 pede confirmação, e `citeck stop seaweedfs` exibe um aviso: enquanto o SeaweedFS estiver parado, não é possível enviar nem baixar arquivos.
- Quando um namespace recebe uma nova chave S3, o launcher também atualiza a cópia dela no ECOS — por exemplo, depois de restaurar um snapshot em um novo namespace ou de redefinir a senha mestra no aplicativo desktop.
- Modo servidor: `citeck install` pergunta onde guardar o conteúdo depois que o release é escolhido (se esse release suportar S3), `citeck setup content-storage` muda o armazenamento de um namespace existente para o S3 (o daemon precisa estar em execução), e `citeck status` mostra uma linha `Content storage:` para um namespace que guarda o conteúdo no S3.
- No aplicativo desktop, os namespaces cujo bundle inclui o SeaweedFS ganharam, na barra lateral, em **Aplicativos**, um link **SeaweedFS** que abre a interface de administração do SeaweedFS (usuário `admin`, senha `admin`). Enquanto o SeaweedFS não estiver em execução (por exemplo, quando o conteúdo fica no banco de dados), o link aparece desativado.
- `citeck setup admin-password` agora lista os aplicativos que continuam aceitando a senha antiga até serem recriados (o SeaweedFS, por exemplo); o `citeck reload` os recria.
- Para autores de workspace: `secrets:` aceita entradas geradas. `- generated: <id>` (`length:` opcional, 16–128, padrão 40) dá a cada namespace o seu próprio valor aleatório, criado uma única vez e depois mantido. Launchers anteriores à 2.16 ignoram essas entradas: neles, um aplicativo que faz referência a uma delas não é gerado enquanto o namespace não tiver um valor salvo.
- Para autores de workspace: uma entrada de `links:` com `category: Apps` ou `Resources` agora entra no grupo correspondente da barra lateral (**Aplicativos** ou **Recursos**) em vez de ganhar um cabeçalho próprio no final.
