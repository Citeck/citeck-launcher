## Nouveautés
- **Stockage du contenu : base de données ou S3.** Un namespace sur un bundle Enterprise qui inclut SeaweedFS (le premier est 2026.3-RC6) peut conserver les fichiers téléversés dans S3 plutôt que dans sa base PostgreSQL : choisissez **S3 (SeaweedFS)** sous **Stockage du contenu** dans la boîte de dialogue de création ou de modification du namespace. **Base de données** reste le choix par défaut, et les namespaces existants conservent leur contenu dans la base. Sur les autres bundles Enterprise, le champ est affiché, mais l'option S3 est indisponible, avec la raison.
- Avec S3, le lanceur démarre SeaweedFS avec le namespace et y connecte de lui-même ecos-content dès que la plateforme est opérationnelle : il n'y a rien à configurer dans ECOS. Si un administrateur a déjà fait d'un autre stockage le stockage par défaut dans ECOS, le lanceur n'y touche pas. Dans l'application de bureau, une bannière du tableau de bord suit la progression et, si la connexion échoue, propose **Réessayer** ; le lanceur réessaie aussi de lui-même.
- Un namespace peut passer plus tard de la base de données à S3, mais pas l'inverse. Les fichiers téléversés avant le changement restent dans la base.
- Dans l'application de bureau, arrêter SeaweedFS dans un namespace qui stocke son contenu dans S3 demande une confirmation, et `citeck stop seaweedfs` affiche un avertissement : tant que SeaweedFS est arrêté, les fichiers ne peuvent être ni téléversés ni téléchargés.
- Lorsqu'un namespace reçoit une nouvelle clé S3, le lanceur met aussi à jour la copie de cette clé dans ECOS, par exemple après la restauration d'un snapshot dans un nouveau namespace ou la réinitialisation du mot de passe principal dans l'application de bureau.
- Mode serveur : `citeck install` demande où stocker le contenu une fois la release choisie (si cette release prend en charge S3), `citeck setup content-storage` passe le stockage d'un namespace existant à S3 (le daemon doit être en cours d'exécution), et `citeck status` affiche une ligne `Content storage:` pour un namespace qui stocke son contenu dans S3.
- Dans l'application de bureau, les namespaces dont le bundle inclut SeaweedFS ont dans la barre latérale, dans le groupe **Applications**, un lien **SeaweedFS** qui ouvre l'interface d'administration de SeaweedFS (utilisateur `admin`, mot de passe `admin`). Tant que SeaweedFS n'est pas démarré (par exemple quand le contenu est stocké dans la base), le lien est grisé.
- `citeck setup admin-password` indique désormais les applications qui acceptent encore l'ancien mot de passe jusqu'à leur recréation (SeaweedFS, par exemple) ; `citeck reload` les recrée.
- Pour les auteurs de workspaces : `secrets:` accepte des entrées générées. `id: <id>` + `generated: {length: 40}` (`length:` facultatif, de 16 à 128, 40 par défaut) donne à chaque namespace sa propre valeur aléatoire, créée une seule fois puis conservée. Nécessite Launcher 2.16 ou une version ultérieure.
- Pour les auteurs de workspaces : une entrée `links:` avec `category: Apps` ou `Resources` rejoint désormais le groupe intégré correspondant de la barre latérale (**Applications** ou **Ressources**) au lieu d'apparaître sous son propre titre en bas.

## Instantanés
- L’option `--include-secrets` exporte les secrets de l’espace de noms, y compris les clés d’authentification et les mots de passe administrateur et du compte de service, vers un autre profil. Ils sont exclus par défaut ; avec cette option, l’archive les contient en clair et doit être protégée.
- L’import restaure les versions des dépendances et les générations des volumes avec les secrets. Un import interrompu bloque le démarrage jusqu’à une nouvelle importation réussie ; la CLI ne redémarre plus l’espace de noms après un échec. Le contenu des volumes reste hors de la transaction des métadonnées.
- Les archives sont vérifiées avant toute modification des données existantes. Les objets S3 externes et la configuration de l’espace de noms ne sont pas inclus.
