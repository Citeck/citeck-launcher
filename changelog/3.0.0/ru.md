## Новые возможности
- **Диагностика JVM без JDK в образе.** `citeck jstack <app>` — дамп потоков, `citeck jmap <app>` — дамп памяти со скачиванием к себе, `citeck jcmd <app> <команда>` — всё остальное, о чём умеет рассказать сама JVM. Работает и когда сервис запускается или падает, а не только когда он работает.
- **`citeck export ls|get|rm`.** У каждого контейнера появился каталог для выгрузки артефактов — дампов памяти, дампов БД, отчётов, — а файлы видны, скачиваются и удаляются из CLI.
- **Веб-приложения Citeck из коробки сохраняют дамп памяти при OutOfMemoryError** — сжатым, в этот каталог. Хранится только самый свежий дамп, поэтому цикл падений не забьёт диск.
- **Все пулы памяти JVM теперь рассчитываются от лимита контейнера** — heap, direct-память, metaspace и code cache. Раньше ограничивался только heap, поэтому утечка в любом другом пуле исчерпывала контейнер, и ядро убивало его без Java-ошибки и без дампа. Заданный вручную heap сохраняется как есть, остальные пулы считаются вокруг него; контейнеру, который нельзя рассчитать безопасно, ставятся только те потолки, которые не могут его сломать.
- **Перед перезапуском сервиса, не прошедшего проверку живости, снимается дамп потоков** — причина остаётся в файле диагностики, а не исчезает вместе с контейнером.

## Исправления
- **Сервис в длинной паузе сборки мусора больше не перезапускается как мёртвый.** Проверка живости теперь допускает около 60 секунд непрерывных отказов вместо примерно 20.
- **Прокси пересоздаётся вместе с gateway.** После правки конфигурации, пересоздавшей gateway, nginx продолжал обращаться по старому адресу, и страницы за gateway отдавали 502, хотя всё выглядело исправным.
- **`citeck diff` больше не утверждает, что перезагрузка выключит HTTPS** на стендах с самоподписанным сертификатом или сертификатом Let's Encrypt.
- **Если заметки к обновлению не загрузились, об этом теперь сообщается** вместо пустого окна.

## Обновление
- При первом запуске после обновления все контейнеры пересоздаются один раз: каждому сервису добавляются каталог выгрузки и новые настройки JVM. На стенде из 17 сервисов это заняло около 5 минут.
