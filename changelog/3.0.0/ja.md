## 新機能
- **イメージに JDK がなくても JVM を診断できます。** `citeck jstack <app>` でスレッドダンプ、`citeck jmap <app>` でヒープダンプを手元にダウンロード、`citeck jcmd <app> <コマンド>` で JVM 自身が報告するその他の情報を取得できます。サービスが起動中や障害中でも実行でき、正常稼働時に限りません。
- **`citeck export ls|get|rm`。** すべてのコンテナに成果物用の出力ディレクトリができました。ヒープダンプ、データベースダンプ、レポートなどを CLI から一覧・ダウンロード・削除できます。
- **Citeck のウェブアプリは OutOfMemoryError 時に標準でヒープダンプを保存します。** 圧縮して同じディレクトリに書き出し、最新のダンプだけを残すため、再起動ループでディスクが埋まることはありません。
- **JVM のすべてのメモリ領域をコンテナの上限から算出するようになりました。** ヒープ、ダイレクトメモリ、メタスペース、コードキャッシュが対象です。従来はヒープだけが制限されていたため、他の領域でリークするとコンテナを使い切り、Java の例外もダンプも残さずカーネルに強制終了されていました。手動で指定したヒープはそのまま尊重し、残りの領域をその周囲で配分します。安全に配分できないほど小さいコンテナには、壊す恐れのない範囲でのみ上限を設定します。
- **ヘルスチェックに失敗してサービスが再起動される前に、スレッドダンプを取得します。** 原因がコンテナとともに消えるのではなく、診断ファイルに残ります。

## 修正
- **長い GC 停止中のサービスが停止扱いで再起動されることはなくなりました。** ヘルスチェックの許容が、連続失敗およそ 20 秒から約 60 秒に広がりました。
- **プロキシは gateway と同時に再作成されます。** gateway を再作成する設定変更のあと、nginx が古いアドレスに転送し続け、gateway 配下のページが 502 を返す一方で、表示上はすべて正常に見えていました。
- **`citeck diff` が「リロードで HTTPS が無効になる」と表示しなくなりました。** 自己署名証明書や Let's Encrypt 証明書を使う名前空間での誤った表示です。
- **更新内容の説明を読み込めなかった場合に、その旨を表示します。** 以前は空のダイアログが出るだけでした。

## アップグレード
- アップグレード後の初回起動で、すべてのコンテナが一度だけ再作成されます。各サービスにエクスポート用ディレクトリと新しい JVM 設定が追加されるためです。17 サービスの名前空間では約 5 分かかりました。
