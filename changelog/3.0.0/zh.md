## 新功能
- **镜像中没有 JDK 也能诊断 JVM。** `citeck jstack <app>` 获取线程转储，`citeck jmap <app>` 获取堆转储并下载到本地，`citeck jcmd <app> <命令>` 获取 JVM 自身能报告的其他信息。服务在启动中或出现故障时同样可用，而不仅限于正常运行时。
- **`citeck export ls|get|rm`。** 每个容器现在都有一个用于产物的输出目录——堆转储、数据库转储、报告——可以在 CLI 中列出、下载和删除这些文件。
- **Citeck 网页应用默认在 OutOfMemoryError 时保存堆转储**，压缩后写入该目录。只保留最新的一份转储，因此崩溃循环不会占满磁盘。
- **JVM 的所有内存池现在都按容器上限计算**：堆、直接内存、元空间和代码缓存。此前只有堆受到限制，任何其他内存池泄漏都会耗尽容器，内核将其杀死，既没有 Java 报错也没有转储。手动设置的堆保持不变，其余内存池围绕它分配；小到无法安全分配的容器，只在不会造成破坏的地方设置上限。
- **服务因健康检查失败而被重启之前，会先抓取线程转储**，原因会留在诊断文件中，而不是随容器一起消失。

## 修复
- **处于长时间垃圾回收停顿中的服务不再被当作已死而重启。** 健康检查现在容忍约 60 秒的连续失败，而不是约 20 秒。
- **代理会与 gateway 一同重建。** 在重建 gateway 的配置变更之后，nginx 仍然路由到旧地址，gateway 后面的页面返回 502，而一切看起来都很正常。
- **`citeck diff` 不再声称重新加载会关闭 HTTPS**（使用自签名证书或 Let's Encrypt 证书的命名空间）。
- **更新说明加载失败时现在会给出提示**，而不是显示一个空对话框。

## 升级
- 升级后首次启动时，每个容器都会重建一次：每个服务都会获得导出目录和新的 JVM 设置。在 17 个服务的命名空间上大约需要 5 分钟。
