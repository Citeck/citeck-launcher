## Nouveautés
- **Observer — l'observabilité du stand.** Un bundle qui nomme l'image `observer` démarre désormais le service avec sa propre base PostgreSQL : réception des logs et de la télémétrie OTLP, interface intégrée sur le port 17016 et supervision de RabbitMQ, PostgreSQL et ZooKeeper du stand. L'indicateur `observer` de `namespace.yml` disparaît — la présence de l'observabilité est décidée par la version que le stand exécute, pas par le fichier du stand ; l'ancienne clé est simplement ignorée. La base de l'observer devient une dépendance gérée à part entière : son propre épinglage de version, sa propre génération de volume, `citeck deps upgrade observer-postgres` et `citeck deps rollback observer-postgres`.
- **Les applications qui arrivent pour la première fois avec un nouveau bundle ne démarrent plus d'elles-mêmes** lorsque le modèle du workspace les liste dans `detachedApps`. Une telle application apparaît arrêtée, avec un bouton Play ; `citeck start <app>` l'active définitivement. Les applications que vous exécutiez déjà ne sont pas touchées — un conteneur existant fait preuve — et si Docker ou le dépôt du workspace ne peuvent pas être interrogés, la décision est reportée au chargement suivant plutôt que devinée.
- **Les bases de données supplémentaires se déclarent dans la configuration du workspace.** La nouvelle section `databases:` (id, image, utilisateur, port, limite mémoire, paramètres serveur, `requiredBy`) fait qu'un cluster PostgreSQL de plus n'exige plus une nouvelle version du launcher, et il reçoit tout ce dont dispose la base principale : épinglage de version, compteur de générations de volume, migration de version majeure et rollback.
- **Rapports sur les mises à jour de dépendances.** Chaque `citeck deps upgrade` et `citeck deps rollback`, ainsi que tout refus de pré-vérification, écrivent un rapport texte dans `logs/reports/` : ce qui a retenu la mise à jour, l'étape où elle s'est arrêtée et les logs des conteneurs temporaires, capturés AVANT que le rollback ne les supprime. Les rapports sont inclus dans l'archive d'informations système (`citeck dump-system-info`) : « ça ne se met pas à jour » a enfin une réponse.

## Changements
- Le launcher ne détache plus les applications de lui-même. Le compagnon d'une application arrêtée (`qdrant` pour `rag`, `stt-sidecar` pour `ai`) démarre maintenant avec le namespace comme n'importe quelle autre application — pour que le stand n'en paie pas le prix, arrêtez-le avec `citeck stop <app>` ou listez-le dans les `detachedApps` du modèle.

## Corrections
- L'archive d'informations système ne masque plus les versions d'images. Une valeur que le même conteneur publie dans un champ non secret — l'utilisateur de base `postgres`, par exemple — n'est plus considérée comme un mot de passe ; auparavant, l'archive entière pouvait sortir avec `***REDACTED***` à la place des tags d'images.
