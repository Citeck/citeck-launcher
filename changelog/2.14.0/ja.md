## 新機能
- **Observer — スタンドのオブザーバビリティ。** バンドルが `observer` イメージを指定していれば、サービスは専用の PostgreSQL と一緒に起動するようになりました。ログと OTLP テレメトリの受信、ポート 17016 の内蔵 UI、そしてスタンドの RabbitMQ・PostgreSQL・ZooKeeper の監視を行います。`namespace.yml` の `observer` フラグは廃止されました。スタンドにオブザーバビリティがあるかどうかは、スタンド自身のファイルではなく、そのスタンドが動かしているリリースが決めます（古いキーは単に無視されます）。Observer のデータベースは本格的な管理対象の依存関係になり、独自のバージョン固定と独自のボリューム世代を持ち、`citeck deps upgrade observer-postgres` と `citeck deps rollback observer-postgres` が使えます。
- **新しいバンドルで初めて現れたアプリは、もう自動では起動しません** — ワークスペースのテンプレートがそれを `detachedApps` に挙げている場合です。そのアプリは停止状態で表示され、再生ボタンが付きます。`citeck start <app>` を実行すれば恒久的に有効になります。すでに動かしていたアプリはこのルールの対象外で、既存のコンテナが証拠として扱われます。Docker やワークスペースのリポジトリに問い合わせられなかった場合は、推測せずに次回の読み込みまで判断を先送りします。
- **追加のデータベースはワークスペースの設定で宣言します。** 新しい `databases:` セクション（id、イメージ、ユーザー、ポート、メモリ上限、サーバー設定、`requiredBy`）により、PostgreSQL クラスタをもう一つ増やすのにランチャーの新リリースは不要になりました。しかもメインのデータベースと同じもの — バージョン固定、ボリューム世代カウンタ、メジャーバージョンの移行とロールバック — がそのまま使えます。
- **依存関係アップグレードのレポート。** `citeck deps upgrade` と `citeck deps rollback` の各実行、および拒否された事前チェックは、`logs/reports/` にテキストのレポートを書き出します。何がアップグレードを止めたのか、どのステップで停止したのか、そして一時コンテナのログ — ロールバックがそれらを削除する「前」に採取したもの — が記録されます。レポートはシステム情報アーカイブ（`citeck dump-system-info`）にも含まれるので、「更新されない」という訴えに答えられるようになりました。

## 変更
- ランチャーがアプリを自動で切り離すことはなくなりました。停止中のアプリのコンパニオン（`rag` に対する `qdrant`、`ai` に対する `stt-sidecar`）も、他のアプリと同じように名前空間と一緒に起動します。スタンドにその負担をかけたくない場合は、`citeck stop <app>` で停止するか、テンプレートの `detachedApps` に記載してください。

## 修正
- システム情報アーカイブがイメージのバージョンを伏せ字にしなくなりました。同じコンテナが機密でないフィールドで公開している値（たとえばデータベースユーザーの `postgres`）は、もうパスワードとは見なされません。これまでは、そのせいでアーカイブ全体のイメージタグが `***REDACTED***` になってしまうことがありました。
